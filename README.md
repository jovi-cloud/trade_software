# Trading Strategy Research Platform

A local, single-user desktop application for researching and improving trading
strategies. Backtesting is one step in the loop, not the point of it:

```
idea → strategy → notes → implement → backtest → analyse → improve → new version → repeat
```

No authentication, no cloud, no broker integration, no live trading. All state
lives in `data/`, which can be zipped, moved, or deleted.

See [ARCHITECTURE.md](ARCHITECTURE.md) for the full design.

**Status:** Phase 0 complete — project foundation. No business logic yet.

## Setup

```bash
git clone <repo> && cd backtesting

make install          # uv sync + npm install
make migrate          # create data/app.db and apply migrations
```

Configuration is optional — the app runs with working defaults. To override:

```bash
cp backend/.env.example backend/.env
```

## Running

```bash
make dev
```

Starts both servers and applies pending migrations first.

**Ports** default to **8001** (API) and **5174** (Vite) so they do not clash with
other apps on 8000/5173. Edit `scripts/ports.env` to change them.

| | URL (default ports) |
|---|---|
| Frontend | http://localhost:5174 |
| API | http://127.0.0.1:8001/api/v1 |
| API docs | http://127.0.0.1:8001/docs |
| Health | http://127.0.0.1:8001/api/v1/system/health |

The dashboard shows a live backend status indicator — green means the API and
database are both reachable.

To run them separately:

```bash
make dev-backend      # uvicorn with autoreload
make dev-frontend     # vite dev server
```

The Vite dev server proxies `/api` to the backend, so the browser only ever
talks to one origin and frontend code always uses relative paths.

## Common commands

```bash

make test             # backend test suite

```

## Project layout

```
backend/          FastAPI application
  app/
    api/          HTTP routes, request/response handling
    services/     use cases (orchestration, transactions)
    repositories/ database queries
    models/       SQLAlchemy ORM
    schemas/      Pydantic DTOs
    engine/       backtest engine — framework-free, importable standalone
    data/         market data storage, import, validation
    domain/       pure domain types
    jobs/         background job runner
    core/         config, logging, paths, ids, errors
  alembic/        migrations
  tests/

frontend/         React + TypeScript + Vite
  src/
    app/          shell, router, providers
    pages/        route-level components
    features/     domain-grouped API hooks and components
    components/   shadcn primitives, charts, shared UI
    lib/          api client, formatting, query keys

data/             ALL user state (gitignored) — database, bars, artifacts, logs
docs/             strategy authoring, metric formulas, decision records
```

Dependency direction is one-way and enforced by `import-linter` on every
`make lint`: `api → services → repositories → models → db`. The engine imports
nothing from FastAPI, SQLAlchemy, or Pydantic.

## Conventions

- **Commits:** Conventional Commits — `feat(engine): fill orders at next bar open`
- **Branches:** `feat/`, `fix/`, `refactor/`, `docs/`, `chore/`
- **Never commit:** `data/`, `.env`, `*.db`, `node_modules`, `.venv`
- **Migrations:** always hand-review autogenerated files; SQLite's limited
  `ALTER` support means batch mode is required for most changes
- **Frontend API types are generated,** never hand-written

Full details in [ARCHITECTURE.md](ARCHITECTURE.md) §8–10.

## Backups

`data/` is never in git. Before any migration that drops or rewrites a column:

```bash
make backup
```

Writes a timestamped `.tar.gz` to `backups/` after checkpointing the SQLite WAL.
